# Feature coverage and competitive scope — v0.3

**Date:** 2026-10-23. **Status:** planning only. **Ambition:** a free, open-source alternative spanning the useful jobs of iMazing, 3uTools, coconutBattery, iExplorer, AnyTrans, Reincubate iPhone Backup Extractor, and Finder/Apple Devices, with additional evidence-centered workflows.

This is an expanded roadmap of **80 feature families**, not a statement of implemented features or exact parity. Every machine-readable item remains `implementation_status: planned` and `atlas_validation: not_implemented_or_device_tested`. Competitors were not installed or benchmarked. Vendor documentation establishes advertised/documented behavior, not universal device/version/platform support. A product missing from a row means **not established in this bounded review**, never “does not support”. The detailed executable-planning record is [FEATURES.json](FEATURES.json); primary sources are in [SOURCES-COMPETITORS.md](SOURCES-COMPETITORS.md).

## 1. What the broader objective changes

The original live-device and full Backup Explorer pillars stay intact. The roadmap now explicitly includes media/music/ringtones, rich record decoders, app/package workflows, backup scheduling, migration, screen capture, developer tools, management and firmware/recovery investigation. Difficult desired features stay visible as conditional or parked requirements. Their appearance in a mockup or backlog must not enable an operation.

The **first full P1 beta retains the accepted v0.2 baseline: known-password encrypted backups plus Messages and Contacts**, as well as raw backup browsing, generic viewers, device/apps, document reads and verified exports. A smaller P0 fixture preview is an internal engineering milestone. P2 is for further decoders and rich imported/analytical views; it must not quietly postpone those P1 commitments.

“Free” is a product policy: no paywall, subscription, mandatory account, export quota or forced cloud service for the local core. It does not prove that signing, test hardware, maintenance or every potential account integration has zero cost. Final dependency/license/distribution decisions belong to the architecture and release plan. The project will implement its own workflows and UI using permitted dependencies and data; no competitor code, paid binaries, proprietary service or private customer data is assumed available.

## 2. Phases and admission rules

| Phase | Meaning |
| --- | --- |
| P0 | Proof work, fixture vertical slice, capability experiments and schema contracts; not public feature completion. |
| P1 | First full read-only beta: device/apps, File Sharing reads, unencrypted and known-password encrypted backups, generic viewers, Messages/Contacts and verified exports. |
| P2 | Richer decoders/imports, media organization, comparable history and evidence-driven analysis. |
| P3 | Separately validated writes, backup creation, scheduling and reversible host workflows. |
| P4 | Conditional companion, account, developer, managed-device and recovery/firmware lanes. |
| PARKED | Desired capability recorded; no justified universal route or unsuitable promise. Preserve supported user handoffs where possible. |

P0 evidence work is required for relevant later rows even where a row has a P1–P4 target. Phase labels are dependency order, not calendar commitments. Host-only export is different from a phone write; any action that can affect user data has an individual contract.

| Gate | Required evidence before admission |
| --- | --- |
| G-FIXTURE | Versioned synthetic fixtures; bounded parsing; malformed/partial inputs; immutable source; measurable coverage. |
| G-LIVE | Pinned adapter and an explicitly selected, authorized test device; model/iOS/build/transport matrix; denied, locked, disconnect and missing-field outcomes. |
| G-EXPORT | Exact selection, resource grouping, destination-space/conflict handling, verified bytes or meaningful record counts, provenance and per-item receipt. |
| G-WRITE | Per-operation capability proof and exact target; preflight and preview; explicit action confirmation; interruption semantics; no blind retry; postcondition verification. |
| G-CRYPTO | Known user-supplied password; reviewed cryptographic implementation and test vectors; no password logs; bounded attempts and plaintext lifetime; wrong-password state. |
| G-ACCOUNT | Supported account interface, access approval where needed, user consent and scoped tokens; no automatic credential or identifier upload. |
| G-COMPANION | Separate signed iPhone app, entitlements, distribution and regional eligibility; revocation, stale data and production-device tests. |
| G-RECOVERY | Sacrificial authorized device and recovery procedure; model/build/signing preflight; refusal of silent erase fallback; independently verified backup and restore results. |
| G-MANUAL | User-supplied evidence with source/date; never overwrite measured values or imply automated validation. |
| G-NO-ROUTE | Keep recorded as desired but unavailable; no runnable control or success simulation until a justified route and revised gate exist. |
| G-OSS | Pinned dependencies, redistribution obligations and notices reviewed; fixture rights; reproducible build, accessibility and offline behavior checked. |
| G-REVIEW | Versioned interpretation and source coverage; distinguish observation, inference, uncertainty and user notes; no unqualified diagnostic verdict. |

## 5. Important corrections for the Codex handoff

1. **iCloud backups and account content are distinct.** Reincubate's own FAQ says remote iCloud backup retrieval is unavailable since May 2020, even though it describes live iCloud content access. AnyTrans's broader migration language is not evidence that Atlas has a supported route. Keep BK-12 parked; DATA-15 is a separate conditional lane. [C14, C16]
2. **Legacy app archive commands are not a current restore solution.** Upstream ideviceinstaller explicitly qualifies legacy archive/restore on newer iOS. Per-app restore needs app/version-specific proof; it is not equivalent to copying Documents. [T04, T24]
3. **Firmware “update” can erase.** The upstream restore README describes an erase fallback when the IPSW has no upgrade variant. Atlas must refuse an implicit fallback and require a separate explicit erase plan. Signed firmware compatibility is another gate. [T07]
4. **A source-documented screen recorder is not a universal controller.** QuickTime provides an official connected-device capture path. Apple Mirroring has its own eligibility rules. An Atlas button can first be a clear supported handoff, not a fictional embedded control API. [T09, T10]
5. **Battery and hardware claims require field-specific proof.** coconutBattery itself qualifies information availability. Software readings, user checks and official Settings evidence must remain distinguishable; a report is not an authenticity certificate. [C10, T17, T18]
6. **Security analysis reports evidence, not certainty.** iMazing describes possible false positives and indicator analysis rather than spyware removal. The future Atlas lane requires transparent match context and source coverage. [C07]
7. **Finder can archive local backups.** Do not repeat “only one recoverable backup”. Atlas can improve exploration, history and automation while acknowledging Apple's archive operation. [C17]
8. **3uTools already has Mac downloads.** The roadmap cannot be marketed as the first Mac equivalent of a Windows-only tool. The presence of Mac builds does not establish that every listed toolbox item is present on Mac. [C09]
9. **“Coming soon” is not shipped coverage.** The AnyTrans screen page labels some editing/format features as future sections. They remain ideas to compare, not verified shipped functionality. [C13]

## 6. Done means evidence, not a checked box

Codex may change an individual feature's status only after linking a committed implementation, applicable capability record, fixture coverage and meaningful verification. Source research alone can advance an evidence state; it cannot set the feature to implemented. P1 native-device claims need the exact tested matrix. Host fixtures and mockups must visibly use synthetic data. If a route remains unavailable, finish the useful supported portion, preserve the gap and provide the documented handoff rather than manufacturing a backend success.

Do not silently add a second shipping transport, license-dependent online service, telemetry, device write, Apple Account sign-in or broad filesystem access merely to increase this table's coverage count. Prioritize a reliable vertical slice, then add feature families behind the same evidence and operation contracts.
